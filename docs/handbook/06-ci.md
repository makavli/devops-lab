# 6. CI and the delivery flow

## The flow
```
branch ─► ./lab check locally ─► push ─► PR ─► CI (./lab check on our runner) ─► review ─► merge (owner)
       ─► Argo CD syncs apps/ from main
```
`main` only changes through merged PRs. CI runs the same command as local: one gate, no surprises.

## The gate: `./lab check`
- `bash -n lab` and shellcheck (if installed: `sudo apt-get install -y shellcheck`).
- kubeconform `-strict` on every manifest (values files excluded), with CRD schemas from the
  datreeio CRDs-catalog for Gateway API, Envoy Gateway, MetalLB, Prometheus Operator and Argo CD.

## Runner: this WSL box (`./lab runner`)
- GitHub-hosted minutes on a private repo are limited (2,000/month free); a self-hosted runner uses none.
- `./lab runner` downloads the latest actions/runner, gets a single-use registration token through gh,
  registers with label `devops-lab`, and installs a systemd service.
- **Never** attach a self-hosted runner to a public repo: a fork's PR could run arbitrary code on this PC.
- Status: `sudo ~/actions-runner/svc.sh status`; logs: `journalctl -u 'actions.runner.*' -f`.
- Remove: `cd ~/actions-runner && sudo ./svc.sh uninstall && ./config.sh remove --token "$(gh api -X POST repos/makavli/devops-lab/actions/runners/remove-token -q .token)"`.

## Workflow (`.github/workflows/ci.yml`)
`permissions: contents: read` (least privilege for the job token), `concurrency` cancels superseded runs,
`timeout-minutes` caps a stuck job. Actions are pinned by major tag; pinning by commit SHA is the stricter
supply-chain practice (exercise).

## Version bumps
Platform versions sit at the top of `./lab`. Bump on a branch, `./lab up`, `./lab check`, look at Grafana
and Argo CD, then PR. Check upstream release notes for CRD changes: Helm does not upgrade CRDs of an
installed chart (kube-prometheus-stack documents a manual `kubectl apply --server-side` of its CRDs).
