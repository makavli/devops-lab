# 6. The delivery flow and the local gate

## The flow
```
branch ─► ./lab check ─► git push (pre-push hook: ./lab check on the pushed commit) ─► PR ─► review
       ─► merge (owner) ─► Argo CD syncs apps/ from main
```
`main` only changes through merged PRs. There is no CI: this is a private repo, and GitHub only stores and
publishes it. GitHub Actions is disabled on the repo (Settings → Actions → General), and `./lab check`
refuses any `.github/workflows/` file. Every test runs on this PC and must pass before a push leaves it.

## The gate: `./lab check`
- `bash -n lab` and shellcheck (if installed: `sudo apt-get install -y shellcheck`).
- No workflow files (the no-CI rule, as code).
- kubeconform `-strict` on every manifest (values files excluded), with CRD schemas from the
  datreeio CRDs-catalog for Gateway API, Envoy Gateway, MetalLB, Prometheus Operator and Argo CD.

## Enforcement: the pre-push hook
`.git/hooks/pre-push` on this PC refuses a push to `main`, commits with a non-noreply email, and added lines
holding personal words. Then it checks out each pushed commit in a throwaway `git worktree` and runs
`./lab check` there, so it tests what is pushed, not the working tree (uncommitted fixes cannot hide a broken
commit). A red check refuses the push.

Hooks are not versioned: a fresh clone has none until the file is copied back. Trade-off against CI: nothing
server-side stops `git push --no-verify` or a push from another clone, so the review is the second line.
In a team, that is the reason CI exists: the server is the one place nobody can skip.

## History: the self-hosted runner (removed 2026-11-21)
Until PR #6 a workflow ran `./lab check` on every PR, on a self-hosted runner in this WSL (`./lab runner`).
The owner's rule since: private repos run no CI, tests run locally only. Git history keeps `./lab runner`
and `ci.yml` if a runner is ever wanted again. Never attach a self-hosted runner to a public repo: a fork's
PR could run arbitrary code on this PC.

## Version bumps
Platform versions sit at the top of `./lab`. Bump on a branch, `./lab up`, `./lab check`, look at Grafana
and Argo CD, then PR. Check upstream release notes for CRD changes: Helm does not upgrade CRDs of an
installed chart (kube-prometheus-stack documents a manual `kubectl apply --server-side` of its CRDs).
