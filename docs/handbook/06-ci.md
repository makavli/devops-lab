# 6. CI, the delivery flow and its gates

## The flow
```
branch ─► ./lab check ─► git push (pre-push hook: ./lab check) ─► PR ─► CI: check + passed ─► review
       ─► merge (owner; main's ruleset requires passed) ─► Argo CD syncs apps/ from main
```
`main` only changes through a merged PR whose `passed` check is green. A ruleset on GitHub enforces it: no
direct push, no force push, no deletion, and the `passed` status check required.

## Gate 1: `./lab check`
- `bash -n lab` and shellcheck (if installed: `sudo apt-get install -y shellcheck`; CI requires it).
- Workflow rules: no self-hosted runner, every action pinned to a full commit SHA (a tag can be moved).
- kubeconform `-strict` on every manifest (values files excluded), with CRD schemas from the
  datreeio CRDs-catalog for Gateway API, Envoy Gateway, MetalLB, Prometheus Operator and Argo CD.
- kubeconform itself is pinned: `./lab tools` downloads the version at the top of `./lab` and refuses it unless
  its SHA-256 matches. Bump the version and the checksum together.

## Gate 2: the pre-push hook
`.git/hooks/pre-push` refuses a push to `main`, commits with a non-noreply email, and added lines holding
personal words. Then it checks out each pushed commit in a throwaway `git worktree` and runs `./lab check`
there, so it tests what is pushed, not the working tree. A red check refuses the push.

Hooks are not versioned: a fresh clone has none until the file is copied back. It saves a CI round trip; the
server-side gates below are the ones nobody can skip.

## Gate 3: CI (`.github/workflows/check.yml`)
- Runs `./lab check` on every pull request, on each push to `main`, and by hand, on GitHub's `ubuntu-latest`
  runners: free for a public repo, a fresh machine every run.
- `passed` is the one check `main` requires, whatever jobs are added later.
- The token only reads (`contents: read`). Only the `issue` job may write issues and comments: red checks open
  `Checks failed on pull request #N` (label `ci-failure`), the next green run closes it, and `close-issue.yml`
  closes it when the PR closes. A fork's token cannot write issues, so forks get none.
- Actions: GitHub-owned only, SHA pinning required (repo settings and `./lab check`). Dependabot proposes the new
  pins once a month (`.github/dependabot.yml`).
- A pull request from an outside contributor runs its workflows only after the owner approves the run.

## Why never a self-hosted runner here
On a public repo anyone can open a pull request, and its workflow code runs on the runner. A self-hosted runner
would run a stranger's code on this PC. Until 2026-11-21, while the repo was private, a runner in this WSL ran CI
(`./lab runner`, kept in git history); it was removed, and CI moved to GitHub's runners when the repo went public.

## Version bumps
Platform versions sit at the top of `./lab`. Bump on a branch, `./lab up`, `./lab check`, look at Grafana
and Argo CD, then PR. Check upstream release notes for CRD changes: Helm does not upgrade CRDs of an
installed chart (kube-prometheus-stack documents a manual `kubectl apply --server-side` of its CRDs).
